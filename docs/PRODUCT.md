# 产品说明（shengcheng）

本文件回答：解决什么问题、给谁用、不做什么、怎么算做成。实现细节与参数契约见 [API.md](./API.md)，测试边界见 [TESTING.md](./TESTING.md)。

## 1. 问题

没有这个插件时，用户要在 DSH 对话里拿到图片或视频，只能离开对话去别处生成、下载、改尺寸、再手动搬进项目目录；而 DSH 里已经配置好的媒体路线（提供方 + 模型）在对话中无法直接调用。代价是三步手工搬运，且每次都要重新记住对方的参数口径。

插件解决的是这一段：**在对话里用已配置的 DSH 媒体路线生成图片或视频，并把结果按确定规则落到本地。**（`README.md:3`）

## 2. 用户与场景

主要使用者是**在 DSH 会话里产出素材的内容作者与运营**：他们在对话里描述要什么图/什么视频，期望结果直接出现在会话工作目录或指定目录，而不是先去别的工具里生成。

次要使用者是**操作 agent 的人**：通过工具参数显式给出 provider/model/尺寸/时长，把生成串进脚本化流程，并在视频提交状态不明时用记录 id 续取结果。

典型场景：

- 纯出图：对话里说「生成一张 16:9 的产品图」，使用已保存的图片路线与比例。
- 图生图：给参考图并要求按参考图尺寸输出（尺寸策略设为 `reference`）。
- 短视频：30 秒以内；提交后若状态不明，用 `shengcheng_video_jobs` 的 `status` / `resume` 续取，而不是重新提交。
- 多窗口共用同一 `DSH_HOME`：设置串行保存，后写者收到冲突提示而不是静默覆盖。

**不面向**：

- 需要对外 HTTP/REST 契约做批量集成的系统方——插件只提供 DSH 工具与设置页自用路由（`/api/shengcheng/*`），不承诺第三方可用。
- 需要剪辑、合成、多轨时间线、字幕的成片制作——插件只产出单个媒体文件。
- 需要本地模型推理或自建推理服务的场景——插件不托管任何模型，只调用 DSH 中已配置的路线。

## 3. 能力边界

**做**：

| 能力 | 事实依据 |
| --- | --- |
| 按已保存路线生成图片或视频，参数可逐次覆盖 | `lib/tools.js:99-107` |
| 图生图，支持按参考图尺寸输出并归一化为 PNG | `lib/tools.js:62-64`、`README.md:9` |
| 图片与视频各配一条兜底路线，符合条件时最多再试一次 | `lib/tools.js:200` |
| 视频任务记录：受理即落盘，可 `status` 查询、`resume` 续取、`list` 列出 | `lib/tools.js:229-288` |
| 产物先写 `.part` 再 `link` 发布，同名不覆盖 | `lib/storage.js:86`、`lib/storage.js:127-144` |
| 保存前用 FFmpeg 校验容器、编码、时长、帧数 | `lib/validate-media.js:88-114` |

**不做**：

- 不重试「提交状态不明」的视频任务：提交可能已被受理，重试会重复生成并重复计费（`lib/tools.js:190`、`README.md:13`）。
- 不自动兜底下列失败：内容审核拒绝、参考图输入方式不明、用户取消、本地权限/参数/保存失败（`lib/tools.js:194`）。
- 不做批量队列或并发调度：两个工具都声明不可并发（`lib/tools.js:111`、`lib/tools.js:239`），一次调用只处理一次生成。
- 不清理已生成的产物文件：只清理任务记录（`lib/jobs.js:64`），产物保留策略未实现。
- 不做跨机同步、不上传云端：设置与任务记录都在本机 `DSH_HOME` 下。

## 4. 验收口径（怎么算做成）

一次交付算做成，需要同时满足：

1. **出得来**：对话里成功生成一次图片与一次视频，返回的 `saved <path>` 文件存在，且能通过 FFmpeg 解码校验（`lib/validate-media.js:88`）。
2. **存得稳**：产物路径不被覆盖；目标无写权限时给出 sandbox 拒绝文案而不是静默失败（`lib/storage.js:46`）。
3. **收得住**：失败信息带阶段名与错误码（`lib/tools.js:87`）；状态不明的视频任务给出 `record_id`，可用 `status` / `resume` 续取（`lib/tools.js:86`）。
4. **设置不打架**：两个窗口先后保存时，后写者收到 409 `settings_conflict` 并提示刷新，而不是互相覆盖（`lib/settings.js:114`）。
5. **测试通过**：`npm test` 全绿（当前 108 项，见 [ACCEPTANCE.md](./ACCEPTANCE.md)）。

## 5. 非功能约束

| 约束 | 值 | 依据 |
| --- | --- | --- |
| 单次尝试超时 | 600 秒，覆盖生成、下载、校验 | `lib/parse.js:3` |
| 工具总超时 | 1 210 000 ms（两次尝试 + 10 秒余量） | `lib/tools.js:95` |
| 视频任务查询超时 | 15 秒；整体 630 000 ms | `lib/tools.js:176`、`lib/tools.js:231` |
| 媒体解码超时 | 60 秒 | `lib/validate-media.js:9` |
| 下载超时 | 180 秒 | `lib/network.js:71` |
| 体积上限 | 参考图 15MB、图片 32MB、视频 256MB | `lib/parse.js:5-7` |
| 像素上限 | 64MP | `lib/validate-media.js:8` |
| 视频时长上限 | 30 秒 | `lib/parse.js:4` |
| 下载安全 | 仅 HTTPS、禁 URL 凭据、私网 DNS 拒绝、连接钉已校验 IP | `lib/parse.js:37`、`lib/network.js:49-68` |
| 存储上限 | 任务记录 200 条、单条 16KB、目录 0o700 / 文件 0o600 | `lib/jobs.js:7-8`、`lib/settings.js:75-86` |
| 并发 | 两个工具非并发安全；模型目录并发 4 | `lib/tools.js:111`、`lib/model-catalog.js:2` |
